## 适用场景
用户准备拜访某企业客户前，需要生成客户业务合作情况的谈参要点，包含：
1. 某行历年准入及投放情况（评级/限额/用信描述）
2. 集团关系树（主要经营及发债主体架构）
3. 集团子公司主体信用及持仓总览动态表格

## 输入变量
用户需提供：
- `客户名称`：需要分析的企业名称（如"象屿集团"）
- `时间区间`：分析年份范围，格式"起始年份-结束年份"（如"2023-2026"）

若用户未提供，使用 `ask_user` 询问。

## 执行步骤

### Step 1：确认输入参数
- 使用 `ask_user` 确认客户名称和时间区间（若用户消息中已包含则跳过）
- 从时间区间解析 `start_year` 和 `end_year`（如 "2023-2026" → 2023, 2026）
- 当前日期作为 `current_date`（格式 YYYY.MM.DD）

### Step 2：第一节 — 某行准入及投放情况

**数据来源**：已加载的"某行信用数据表"（required_files 中声明的必需文件）

**处理逻辑**：
1. 在数据表中筛选 `客户名称 = {{客户名称}}` 且年份在 `[start_year, end_year]` 范围内的记录
2. 按年份升序排列
3. 提取每条记录的主体评级、风险限额、用信情况描述
4. 若无匹配记录，输出"未找到与之匹配的数据"

**输出模板**：
> 经查询，"{{客户名称}}"在 {{year1}} 年主体评级为 {{rating1}}、风险限额为 {{limit1}}、用信情况描述为"{{desc1}}"，在 {{year2}} 年主体评级为 {{rating2}}……

### Step 3：第二节 — 集团关系树解析

**处理逻辑**：
1. **优先**：从 groups.yaml 查找 `{{客户名称}}` 的集团关系树
2. **若无配置**：调用 web_search 搜索 "{{客户名称}} 集团 子公司 控股" 等关键词，尝试构建关系树
3. **网络检索交互规则**：明确告知用户"未找到预设的集团关系树，通过网络检索到如下关系：……。是否采用？请回复'是'或'否'或手动修正。"
4. **若网络检索也失败**：输出"未找到与之匹配的数据"

**判断客户角色**：
- 客户名称 = 集团总公司 → 情况一（总公司视角）
- 客户名称是某子公司 → 情况二（子公司视角）
- 无集团关联 → 情况三（孤立企业）

**输出格式（树状缩进，使用 ├─ └─ 符号）**：

情况一（总公司）：
```
{{客户名称}} 集团关系树：
├─ {{集团总公司名称}}（集团总公司）
   ├─ {{子公司1}}（控股XX%）
   └─ {{子公司2}}（控股XX%）
```

情况二（子公司）：
```
{{客户名称}} 所属集团关系树：
{{集团总公司名称}}（集团总公司）
├─ {{子公司1}}（控股XX%）
└─ {{客户名称}}（当前查询主体）
```

控股比例未知时不显示百分比。

### Step 4：第二节 — 集团子公司主体信用及持仓总览

**子公司列表**：从 Step 3 的集团关系树中提取发债主体列表（`subsidiary_list`）。若无法获取，使用 `ask_user` 请求用户提供。

**表格结构**：
- 第1列：指标名称（固定）
- 第2列起：依次为各子公司名称
- 最后列：合计

**指标行生成规则**：

对 `y` 从 `start_year` 到 `end_year` 循环，每年生成两行：
- `{y}年末级别`：子公司在 y 年 12 月 31 日的主体评级（从理财信用数据表或 run_sql 查询，缺省填 "-"）
- `{y}年末限额`：子公司在 y 年末生效的限额（亿元，缺省留空）

完成年份循环后，追加以下固定指标行（current_date 替换为实际日期）：

| 指标 | 合计列处理 |
|------|-----------|
| `{current_date}存续债余额` | 求和 |
| `{current_date}级别` | 填 `/` |
| `{current_date}限额` | 求和 |
| `{current_date}持仓-半穿透` | 求和 |
| `{current_date}持仓-全穿透` | 求和 |
| `{current_date}剩余可用限额` | 求和（= 限额合计 − 半穿透合计）|
| `{current_date}信用政策（评级7）` | 填 `/` |
| `{current_date}直投持仓的最长期限/最高收益率` | 填 `/` |

**数据来源优先级**（每个指标依次尝试）：
1. 已加载的理财信用数据表（optional_files）
2. run_sql 查询已加载的持仓表/评级表
3. 缺省填 "-" 或留空，不影响其他列

**输出格式**：Markdown 管道表格

### Step 5：汇总输出
将以上各节按顺序输出完整报告，格式为 Markdown，章节标题为：
1. 某行准入及投放情况
2. 某某理财准入情况和持仓情况
   - 2.1 主要经营及发债主体架构
   - 2.2 集团子公司主体信用及持仓总览

## 输出格式
Markdown 报告，可导出为 Word（通过 render_report 工具）。

## 注意事项
- 若理财信用数据表未上传，持仓及评级相关指标列全部填 "-"，不阻断流程
- 历史年份评级/限额：若已加载多年历史数据文件，自动拼接；否则填 "-"
- 剩余可用限额为负值时，用 ⚠️ 标记
- 网络检索的集团关系树必须经用户确认后才能使用（ask_user 交互）
- 本 Skill 为 Type C 确定性数据管道，Agent 应忠实按步骤执行，不自由发挥
