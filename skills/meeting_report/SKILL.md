## 适用场景
用户需要生成某个集团系（单一主体或多主体集团）的参谈要点报告，汇总当前持仓、限额、评级情况，支持业务拜访使用。

## 前提条件
必须已加载：
- **主体评级表**（rating_entity_YYYYMMDD）：含主体名称、内部评级、理财限额、已占用限额、剩余可用限额
- **持仓表**（holding_YYYYMMDD）：含限额占用方主体、资产市值等
- **债券评级表**（rating_bond_YYYYMMDD，可选）：含债券明细评级

## 执行参数
- `group_name`：集团系名称（如"象屿系"），从 groups.yaml 获取主体列表
- 如果是单一主体（如"象屿集团"），则自动查询该单一主体

## 数据计算规则

### Step 1：识别集团系成员
从 groups.yaml 获取集团成员列表，如不存在则提示用户使用 `/group add` 命令定义。

### Step 2：各主体限额及评级查询
```sql
SELECT
  主体名称,
  内部评级结果,
  预警等级,
  理财限额,
  已占用限额,
  剩余可用限额,
  "品种（信用政策）",
  评级有效期
FROM rating_entity_table
WHERE 主体名称 IN (?, ?, ...)   -- 集团成员列表
ORDER BY 理财限额 DESC
LIMIT 50
```

### Step 3：各主体持仓汇总（含期限分层）
```sql
SELECT
  限额占用方主体,
  SUM("资产市值_穿透后") AS 全穿透持仓合计,
  SUM("资产市值_半穿透") AS 半穿透持仓合计,
  SUM(CASE WHEN 剩余期限 <= 1 THEN "资产市值_穿透后" ELSE 0 END) AS "1年以内",
  SUM(CASE WHEN 剩余期限 > 1 AND 剩余期限 <= 2 THEN "资产市值_穿透后" ELSE 0 END) AS "1-2年",
  SUM(CASE WHEN 剩余期限 > 2 THEN "资产市值_穿透后" ELSE 0 END) AS "2年以上",
  COUNT(DISTINCT 资产代码) AS 持仓品种数
FROM holding_table
WHERE 限额占用方主体 IN (?, ?, ...)
GROUP BY 限额占用方主体
LIMIT 50
```

### Step 4：在存续债明细（可选，如已加载债券评级表）
```sql
SELECT
  债券名称,
  债券代码,
  持仓金额,
  内部评级结果,
  外部评级,
  到期日,
  评级有效期
FROM rating_bond_table
WHERE 限额占用主体 IN (?, ?, ...)
ORDER BY 持仓金额 DESC
LIMIT 30
```

### Step 5：集团系合计行计算
对 Step 2 和 Step 3 的结果，在 Python 层计算合计行：
- 合计理财限额 = 各主体理财限额之和
- 合计已占用 = 各主体已占用之和
- 合计剩余可用 = 各主体剩余可用之和
- 合计全穿透持仓 = 各主体全穿透持仓之和

## 人工确认节点
展示 Step 2-5 的汇总表格（准入及持仓情况表），用户确认后继续生成报告。

## 报告输出
- 模板文件：`template.md.j2`（同目录）
- **表格内容**：全部来自精确计算，不调用 LLM
- **文字分析**（调用企业内网 LLM）：
  - 集团系投资逻辑与风险提示
  - 与同区域类似集团的横向对比（如数据中有其他集团）
  - 参谈建议要点
- 输出路径：`data/outputs/参谈要点_{集团名称}_{日期}.md`

## 注意事项
- 若集团系成员在主体评级表中找不到，提示用户确认主体名称
- 历史评级（如23年末、24年末）若已加载历史评级文件，自动拼接展示；否则在对应列填"待补充"
- 剩余可用限额为负值时，标红提示（在 Markdown 中用 ⚠️ 标记）
