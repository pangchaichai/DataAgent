## 发现的问题

| # | 优先级 | 分类 | 问题描述 | 复现步骤 | 
|---|--------|------|---------|---------|
| **1** | **P0** | 上传 | **文件上传改为两步流程 (/api/upload → /api/upload/confirm)，且 table_type 未正确传递** — 用户指定 holding 但最终入库为 unknown | POST /api/upload (table_type=holding) → 返回预览 (无 table_name) → POST /api/upload/confirm → 表类型为 unknown |
| **2** | **P0** | 上传 | **v1.6 的单步上传 API 被移除** — 旧版前端和自动化测试基于旧接口，直接 breaking change | POST /api/upload 不再加载数据，仅返回预览 |
| **3** | **P0** | API | **report API 端点不可达 (/api/report/generate 404)** — report_api.py Blueprint 可能未正确注册或路由不匹配 | POST /api/report/generate → 404 |
| **4** | **P1** | Skill Builder | **校验响应格式不匹配** — api/skill_api.py 返回 `{ok, issues}` (扁平)，ui/js/skill_builder.js 读取 `d.validation` → v 为空 → 发布按钮永远 disabled | 进入 Skill Builder → AI生成 → 校验 → 发布按钮灰色不可点击 |
| **5** | **P1** | API | **API 路由无法静态发现** — create_flask_app() 内部 `init_duckdb_connection()` 操作持久化 DuckDB 文件，当运行中的应用持锁时，任何 tools.py 等诊断脚本无法重复调用 create_flask_app() 来列出路由 | python -c "from main import create_flask_app; app = create_flask_app()" → IOError: Conflicting lock |
| **6** | **P1** | 会话 | **删除不存在会话返回 ok:true** — /api/sessions/{id} DELETE 静默返回成功，前端无法区分"已删除"和"不存在" | DELETE /api/sessions/000000000000 → {ok: true} |
| **7** | **P1** | 搜索 | **web_search 工具无独立 REST API** — 只能通过 Agent tool-calling 间接调用，无法直接测试或使用 | 所有 /api/search /api/web-search /api/tool/search → 404 |
| **8** | **P2** | 内存 | **内存增长偏快** — 启动 149MB → 12分钟后 207MB (+58MB)，可能 leak | /api/health 多次采样 |
| **9** | **P2** | 体验 | **Skill Builder AI 生成失败时错误信息不友好** — "AI 生成失败，请重试"未说明原因 (API key缺失) | 无 LLM key 时点击 AI 生成 |

## UAT 结论

**v2.0 不建议当前状态发布。** 

需要修复的问题按优先级：
1. P0: 修复上传流程（恢复单步 API 或补全两步流程的 table_type 传递）
2. P0: 修复 report API 路由注册
3. P1: 修复 Skill Builder validate 响应格式
4. P1: 修复 session delete 404 响应
5. P2: 优化 LLM key 缺失时的错误提示

架构评估：
- Blueprint 拆分 (I-7) 方向正确，但测试覆盖为 0% 是最大风险
- Plan-Execute Agent (I-8) 因 LLM key 缺失未能在 UAT 中验证
- JS 模块化 (I-10) 工程化提升明显，但未引入 JS 测试
- DuckDB 持久化 (I-7) 引入了文件锁问题，影响诊断和并发
